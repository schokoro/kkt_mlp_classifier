## Последовательность проверок

**А. Инвентаризация входа.** Узнай число строк, схему Parquet, количество пустых и дублей по `name`, примерную длину наименований и размер файла. Для входа около 1 млн можно использовать Polars или PyArrow, не меняя файл. Не публикуй сырые наименования без необходимости. Сопоставь параметры источника с существующими метаданными S01.

**Б. Малый автономный fit.** При совпадении CLI с текущим кодом начни с команды:

```bash
/usr/bin/time -v .venv/bin/python scripts/fit_vectorizer.py \
  --input data/corpus.pqt \
  --output outputs/S02/tfidf_100k \
  --max-rows 100000 \
  --features-preset default \
  --seed 42 \
  --source-id corpus_1m_v1
```

Если `/usr/bin/time` отсутствует, используй доступный способ замера и документируй его. Не перезаписывай существующий каталог: подбери другой путь или согласуй.

**В. Полный подготовленный корпус.** Если результаты Б позволяют разумно ожидать, что хватит RAM/диска, выполни аналогичный fit с `--max-rows 1000000` и отдельным `--output outputs/S02/tfidf_1m`. Сохрани `vectorizer_meta.json`, размеры vocab, времена, пиковый RSS, статистику `rows_used`/`rows_fit`, `truncated`, fingerprint файла. Учитывай, что текущий S01 использует префикс корпуса, а не случайный сэмпл. Если размер/ресурсы делают запуск небезопасным, не запускай вслепую и зафиксируй причину.

**Г. Целостность признаков.** Проверка `FeatureBuilder`: загрузка автономного артефакта, порядок признаков, char/word границы, IDF и CSR `transform` для одного набора строк до/после сериализации. Используй существующие функции и тесты; если нужно добавить регрессионный тест — делегируй через отдельный `codex exec`.

**Д. Pretrained train + inference smoke.** На **малой размеченной фикстуре** (например, после `scripts/make_fixtures.py`) проверь загрузку `outputs/S02/tfidf_1m` через `features.mode=pretrained`, обучение облегчённой MLP и последующий инференс из сохранённого артефакта. Для снижения нагрузки допустимо указать `model.hidden=[64]`, `model.dropout=[0.1]`, `train.epochs=1`, `train.device=cpu`, `train.scheduler=none`. Это **технический smoke-тест**, метрики классификации не интерпретировать как качество модели.
